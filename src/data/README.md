## Как добавить оффлайн-видео

Файл ролика в git не кладётся. В репозитории только карточка: публичная ссылка Яндекс.Диска, размер и контрольные суммы. Само mp4 качается в телефон или браузер в момент нажатия «Скачать».

Три места, которые должны совпасть:

1. `stories.json` — текст серии. Поля: `slug` (`s01e18c`), `code` (`S01E18C`), `season`, `number`, `suffix` (`c` у литерной, иначе `""`), `title`, `date` (`YYYY-MM-DD`), `telegramId` (число из `t.me/yurec_xuec/491`), `youtubeId` (11 символов из адреса ролика, без `shorts/`), `body`, `kind` (`episode`), `minutes`, `tags`, `excerpt`. Литерная серия встаёт сразу после своей буквы: `s01e18`, потом `s01e18b`, потом `s01e18c`. Сортировка сама смотрит на сезон, номер и букву.
2. `videos.json` — карточка в разделе «Медиа». `id` = тот же YouTube id. `code` и `storySlug` = slug серии. `kind`: `episode` для серии, `short` для шортса, `song` для песни, `visit` для визита, `call` для звонка. `thumb`: `/thumbs/s01e18c.jpg?v=НОМЕР`. Обложку качает `scripts/fetch-yt-thumbs.py` (берёт кадр с YouTube, если файла ещё нет). Свой кадр кладётся руками в `public/thumbs/` и тогда скрипт его не перетирает.
3. `offline-index.json` — то, по чему работает кнопка «Скачать».

### Ссылка Яндекс.Диска

Ролик заливается на Диск как отдельный файл, не в закрытую папку. Ссылка должна открываться без входа: вид `https://disk.yandex.ru/i/XXXXXXXX`. Именно она пишется в поле `url`. Прямую ссылку на файл (`downloader.disk.yandex.ru/...`) в JSON не класть: она протухает. Приложение само спрашивает её в момент нажатия:

`https://cloud-api.yandex.net/v1/disk/public/resources/download?public_key=` + публичный url.

Тот же запрос без `/download` отдаёт паспорт файла. Его и сверяют перед записью:

```
https://cloud-api.yandex.net/v1/disk/public/resources?public_key=https://disk.yandex.ru/i/XXXXXXXX
```

Оттуда берутся:

| Поле JSON | Откуда |
|---|---|
| `file` | `name` на Диске. Канон: `s01e18c — Юрец в Курске 🌇.mp4` (длинное тире) |
| `size` | `size`, байты, число, не строка |
| `sha256` | `sha256`, строчными буквами |
| `md5` | `md5`, строчными |
| `url` | та публичная ссылка, которую прислали |
| `id` | slug серии (`s01e18c`), не YouTube id |
| `videoId` | YouTube id, тот же, что `videos.json` → `id` |
| `storySlug` / `code` | slug серии |
| `title` | название без эмодзи в конце, эмодзи остаётся в `file` |
| `kind` | как у ролика: `episode`, `short`, `song`, `visit`, `call` |
| `duration` | `м:сс` с YouTube или из `ffprobe` |

После нового пункта поправить шапку файла: `count` = число объектов в `items`, `bytes` = сумма всех `size`. Иначе менеджер оффлайна врёт про объём пакета.

### Контрольная сумма

SHA-256 — это проверка, что скачалось то самое, а не оборванный кусок и не чужой файл.

- Автор присылает сумму рядом со ссылкой. Её сравнивают с полем `sha256` из API Диска. Если не сошлось — на Диск залит не тот файл, в индекс не писать.
- В JSON сумма лежит строчными, без пробелов и без `SHA256:`.
- Android (`YurecOffline.java`) считает SHA-256 по скачанному файлу и сравнивает без учёта регистра. Не сошлось — файл выбрасывается.
- Сайт (`src/lib/offline.ts`) считает ту же сумму в браузере и сравнивает со строчной записью. Текст ошибки: «SHA256 не сошёлся». Файлы больше 80 МБ в браузере не хешируются целиком, на телефоне проверяются всегда.
- MD5 в индекс пишется для сверки с Диском, плеер на него не смотрит.

Проверить файл у себя, если он уже на диске:

```
sha256sum "s01e18c — Юрец в Курске 🌇.mp4"
```

### Что сделать после правки

1. `python3 scripts/fetch-yt-thumbs.py` — докачает недостающую обложку в `public/thumbs/`.
2. `sh scripts/pack-www.sh` — перепишет `android/app/src/main/assets/www/data.js`. Без этого APK и сайт на Pages не увидят серию.
3. Коммит: json + `www/data.js` + новая обложка. Сам mp4 не коммитить.
4. Номер сборки — по правилам `AGENTS.project.md`. Оффлайн-кнопка на уже выпущенном APK читает индекс из сборки, поэтому новая серия появляется после обновления приложения, а не «сама по воздуху».
